# Retrieval evaluation — 2026-10-25

Command: `node scripts/retrieval-eval.mjs demo`
Corpus: **15 documents, 22 chunks** (demo tenant, seeded by `scripts/seed-demo-knowledge.mjs`)
Questions: **16 answerable + 4 off-topic**, listed in `questions.json`
Embedding model: `voyage-4-lite`, 1024 dimensions, `input_type: query|document`

## The one miss

`do you install laminate counters?` returned **Services** at rank 2, not rank 1.

Both *Services* ("we do not install laminate counters") and *Brands and materials*
("counters are quartz, quartzite, granite…") share the words *install* and
*counters*; only *Services* contains *laminate*. Cosine put the other document
first by a small margin. It is still inside the top 3, so the agent receives the
right passage and can answer correctly — but the ranking is worth knowing about.

Not fixed, deliberately: a lexical-overlap boost would probably flip it, and
would also change behaviour on every other question. One documented miss on a
16-question set is a better trade than an unmeasured tweak.

## What the previous run found

Before the stopword fix, `do you sell gift vouchers?` returned *Maintenance
plans* at 0.244 — because that document says "we do not **sell** a maintenance
plan". Off-topic false positives were 25%. Adding generic commerce verbs
(`sell`, `buy`, `offer`, `provide` and their inflections) to the stopword list
took them to zero. The same class of bug had already appeared once with `work`.

## Reproducing

```
node scripts/seed-demo-knowledge.mjs   # seeds the corpus (needs the demo tenant)
node scripts/retrieval-eval.mjs demo   # requires EMBEDDING_* in .env.local
```

Both make at most one embedding request each. Voyage's no-card tier allows
roughly 2–3 requests per minute, so leave a gap between runs.
